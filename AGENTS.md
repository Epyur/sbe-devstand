# AGENTS.md — sbe-devstand (Стенд разработки)

Клиентский плагин-стенд для разработки SBE-плагинов **вне реестра**. Без своего
сервера: публикует `sbe-devstand` в мост `window.SBE` и раздаёт другим плагинам
read-only доступ к боевым LLM/Базе знаний/почте через центральный `dev-gateway`,
плюс адрес и токен локального сервиса для отработки записи.

Дизайн — `docs/superpowers/specs/2026-10-02-sbe-devstand-design.md`, план —
`docs/superpowers/plans/2026-10-02-sbe-devstand-plan.md`. Плагин **в реестр ЦУП
не входит** и ставится вручную; в `sbe-apstore` для него добавлен лишь `dev` в
белый список выдачи токенов.

## Статус

**v0.1.2 (2026-10-03) — модели LLM: список у оператора и выбор в настройках.**
«Проверить LLM» отдавала `undefined`: LLM-центр отвечает `{ data: [...] }`
(провайдерский формат), а клиент брал `.length` у объекта. Разбор исправлен.
В настройках появилось поле **«Модель LLM по умолчанию»** — выпадающий список
моделей, доступных у оператора (подтягивается у LLM-центра, устаревшие с
пометкой; «Как решит сервер» — пусто). `llm.complete()` теперь по умолчанию
берёт выбранную модель (явная в вызове → из настроек → «решит сервер»).
Серверная часть не менялась. `npx tsc --noEmit` EXIT=0, `npm run build` OK.

**v0.1.1 (2026-10-02) — почта в стенде: только письма, шаблон убран.**
Живая ошибка при «Проверить почту»: сервис отдаёт DOCX-шаблон (бинарный), а
клиент разбирал ответ как JSON — падало с ошибкой и кракозябрами из тела файла.
`mailer.template()` убран совсем (разработчику нужны письма, а не шаблон),
остался `mailer.pull()` → `{ emails: [...] }` с телом письма; в клиенте
добавлена защита — не-JSON ответ даёт понятную ошибку, а не парсится как JSON.
На сервере (dev-gateway) `/api/mailer/template` убрана из белого списка и
схемы. `npx tsc --noEmit` EXIT=0, `npm run build` OK.

**v0.1.0 (2026-10-02) — создан.** Каркас: мост-сервис `SbeDevstandApi`,
клиент `dev-gateway`, раздел настроек (профиль, интеграции, локальный стенд,
справка). Локальный комплект `sbe-devstand-kit` — отдельный репозиторий.
`npx tsc --noEmit` EXIT=0, `npm run build` OK. Реальное подключение к
боевому шлюзу проверяется после его деплоя.

## Структура

- `src/main.ts` — `SbeDevstandPlugin`: `publishService`/`unpublishService`,
  настройки.
- `src/services/dev-client.ts` — `DevClient` (реализует `SbeDevstandApi`):
  `getToken('dev')` через `sbe-apstore`, `requestUrl` на `/api/dev/*`,
  обработка 401/403/404, фильтрация выключенных интеграций.
- `src/ui/settings-tab.ts` — разделы: Профиль (`whoami`), Интеграции (LLM/KB/
  почта — вкл/выкл + проверка), Локальный стенд (адрес, токен), Справка.
- `src/types/settings.ts` — `SbeDevstandSettings`.
- `src/styles.css` — `tn-devstand-*`.

## Ключевые решения

- Только свободные зависимости; импорты sbe-core относительные
  (`../../sbe-core/src/...` из `src/`, `../../../sbe-core/src/...` из
  `src/services|ui/`).
- `local` — только адрес и токен из настроек; писать должен сам плагин
  разработчика в свой локальный сервис.
- Новость в ЦУП (`announceUpdate`) сознательно не подключена: плагин вне
  реестра, в `dev`-приложении новости не публикуются.

## «Фиксируй» — релиз ОБЯЗАТЕЛЕН

Стенд **не входит в реестр ЦУП**, поэтому обычный путь обновления (ЦУП →
самораздача плагина) для него не работает. Значит, «Фиксируй» для `sbe-devstand`
— это НЕ только коммит и пуш: **обязательно ещё опубликовать GitHub-релиз**, иначе
обновиться у людей нечем.

Порядок «Фиксируй»:

1. бамп версии в `manifest.json` и `package.json`;
2. `npm run build` (собирает `main.js` и `styles.css`);
3. коммит + пуш в `main`;
4. `gh release create v<версия> manifest.json main.js styles.css --title … --notes …`
   — обычный релиз. Для «бета»-сборки тот же вызов с флагом `--prerelease`
   (GitHub пометит её «Pre-release»). Это и есть бета-канал стенда — отдельного
   канала установки в ЦУП у него нет.

Установка и обновление у разработчика — из релиза: скачать три файла
(`manifest.json`, `main.js`, `styles.css`) в `<вольт>/.obsidian/plugins/sbe-devstand/`
и включить плагин. См. `README.md`.

## Правила

- Всё, что попадает в релиз, собирается ДО тега: `main.js`/`styles.css` в
  репозитории и в ассетах релиза обязаны совпадать.
- Не-JSON ответ сервиса (например, бинарный файл) не парсить как JSON — клиент
  обязан давать понятную ошибку, а не показывать содержимое файла (был баг с
  шаблоном письма).
- `catch(e: unknown)` + `errorMessage()`; `requestUrl()`; без `any`; классы
  `tn-*`; UI на русском; автор — Полищук Евгений (polishchuk@tn.ru).
- Коммиты/пуши/релиз — по явной команде.
